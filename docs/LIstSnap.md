# LiteLauncher 截图贴图插件 PRD

## 1. 产品名称

暂定名称：**LiteSnap**

备选名称：

* LiteSnap
* LitePin
* SnapPin
* ScreenPin
* ClipPin

推荐使用：**LiteSnap**

原因：
名称短，容易理解，既包含截图 Snap，也可以延展到贴图、标注、OCR、颜色拾取等能力。

---

## 2. 产品定位

LiteSnap 是 LiteLauncher 内置的截图贴图插件，面向 Windows 重度用户、开发者、设计师和办公用户，提供快速截图、区域标注、贴图悬浮、剪贴板转贴图、图片管理等能力。

它不是单独做一个大型截图软件，而是作为 LiteLauncher 的一个高频效率插件存在。

核心定位：

> 按下快捷键，截图、标注、复制、贴到屏幕上，一次完成。

---

## 3. 背景与问题

用户在日常工作中经常遇到以下场景：

1. 需要截取错误信息并贴到聊天窗口。
2. 需要把一段接口文档、表格、设计图、错误提示固定在屏幕上，边看边写代码。
3. 需要快速给截图加箭头、框选、文字说明。
4. 需要把剪贴板里的图片或文字临时变成屏幕上的悬浮卡片。
5. 需要对比两个窗口内容，但窗口切来切去很麻烦。
6. Windows 自带截图工具可以截图，但“贴图参考”和“高频标注”能力不够顺手。
7. Snipaste 很强，但 LiteLauncher 可以把截图、贴图、剪贴板、启动器、开发者工具组合到一个入口里。

因此，LiteLauncher 需要一个内置截图贴图插件，补齐“视觉信息处理”的高频操作闭环。

---

## 4. 产品目标

### 4.1 MVP 目标

第一版目标不是完全替代 Snipaste，而是完成最核心的 4 个动作：

1. 快速区域截图。
2. 截图后进行基础标注。
3. 截图复制到剪贴板。
4. 截图贴到屏幕上成为悬浮图片窗口。

### 4.2 中期目标

1. 支持剪贴板图片转贴图。
2. 支持贴图窗口缩放、透明度、置顶、点击穿透。
3. 支持截图历史。
4. 支持多屏幕截图。
5. 支持颜色拾取。
6. 支持 OCR 识别。
7. 支持截图自动保存和快速命名。

### 4.3 长期目标

1. 做成 LiteLauncher 的核心插件之一。
2. 和剪贴板插件联动。
3. 和 Markdown / OCR / 图片压缩 / 二维码识别插件联动。
4. 支持插件命令化，例如 `snap`, `pin`, `ocr`, `color`。
5. 形成 LiteLauncher 区别于普通启动器的重要功能壁垒。

---

## 5. 非目标

第一阶段不做以下能力：

1. 不做完整图片编辑器。
2. 不做复杂图层系统。
3. 不做云同步。
4. 不做团队协作。
5. 不做录屏。
6. 不做长截图。
7. 不做第三方截图插件市场。
8. 不完全复制 Snipaste 的所有交互。

第一版只做高频刚需：**截图、标注、复制、贴图、关闭**。

## 7. 核心用户路径

### 7.1 截图并复制

用户路径：

1. 用户按下截图快捷键。
2. 屏幕进入截图模式。
3. 用户拖拽选择区域。
4. 松开鼠标后出现截图工具栏。
5. 用户点击复制，截图进入剪贴板。
6. 用户粘贴到微信、飞书、文档或 Issue 中。

默认快捷键建议：

```text
Alt + Shift + A
```

可选命令：

```text
snap
截图
```

---

### 7.2 截图并贴图

用户路径：

1. 用户按下截图快捷键。
2. 拖拽选择区域。
3. 截图完成后点击“贴图”。
4. 截图作为独立悬浮窗口出现在屏幕上。
5. 用户可以拖动、缩放、调整透明度、关闭。
6. 用户边看贴图边处理其他事情。

默认快捷键建议：

```text
Alt + Shift + S
```

可选命令：

```text
pin
贴图
```

---

### 7.3 剪贴板图片转贴图

用户路径：

1. 用户复制一张图片。
2. 打开 LiteLauncher。
3. 输入 `pin`。
4. 当前剪贴板图片被贴到屏幕上。
5. 用户可以拖动和缩放该贴图。

可选快捷键：

```text
Alt + Shift + V
```

---

### 7.4 截图后标注

用户路径：

1. 用户截图。
2. 进入标注状态。
3. 用户选择矩形、箭头、画笔、文字、马赛克。
4. 标注完成后复制、保存或贴图。

第一版标注工具：

* 矩形
* 箭头
* 画笔
* 文字
* 马赛克
* 撤销
* 清除标注

---

### 7.5 截图历史

用户路径：

1. 用户打开 LiteLauncher。
2. 输入 `snap history`。
3. 展示最近截图列表。
4. 用户可以复制、贴图、保存或删除。

第一版可以先不做完整 UI，只保留最近 20 条截图记录。

## 8. 功能需求

## 8.1 截图模式

### 功能描述

用户通过快捷键或 LiteLauncher 命令进入截图模式。

### 需求说明

1. 支持全屏遮罩。
2. 支持鼠标拖拽选择区域。
3. 支持显示选区尺寸。
4. 支持 ESC 退出截图。
5. 支持 Enter 确认截图。
6. 支持双击确认截图。
7. 支持多屏幕基础兼容。
8. 支持高 DPI 显示适配。

### 交互细节

进入截图模式后：

* 屏幕变暗。
* 鼠标变成十字选择状态。
* 用户拖拽生成选区。
* 选区边框高亮。
* 选区旁显示尺寸，例如 `842 × 418`。
* 松开鼠标后展示浮动工具栏。

### 优先级

P0

---

## 8.2 截图工具栏

### 功能描述

截图完成后，在选区附近展示操作工具栏。

### 第一版工具栏按钮

1. 复制
2. 保存

4. 矩形
5. 箭头
6. 画笔
7. 文字
8. 马赛克
9. 撤销

### 交互要求

1. 工具栏位置跟随选区。

3. 鼠标 hover 显示 tooltip。
4. 点击复制后自动退出截图模式。
5. 点击贴图后生成悬浮贴图并退出截图模式。
6. 点击保存后弹出保存路径或按默认规则保存。

### 优先级

P0

1. 默认保存目录。
2. 保存格式：PNG / JPG。
3. 是否复制后自动保存。

P1

### 优先级

P2

## 8.9 OCR 识别

### 功能描述

用户截图后可以识别图片中的文字。

### 第一阶段建议

不在 MVP 中实现 OCR，但预留按钮和架构。

### 后续实现方式

可选方案：

1. 本地 OCR：PaddleOCR / Tesseract。
2. 系统 OCR：Windows OCR 能力。
3. 云端 OCR：后续可配置大模型或第三方 API。

### 注意事项

1. OCR 涉及隐私，默认应本地优先。
2. 云端 OCR 必须明确提示用户。
3. OCR 结果可以和剪贴板插件联动。

### 优先级

P3

## 11. 交互设计

## 11.1 截图状态

截图状态分为 5 个阶段：

```text
Idle
Selecting
Selected
Annotating
Completed
```

### Idle

默认状态，等待用户触发。

### Selecting

用户正在拖拽选择区域。

### Selected

用户已经完成区域选择，展示工具栏。

### Annotating

用户正在标注。

### Completed

用户完成复制、保存或贴图动作，退出截图模式。

## 12.2 截图实现思路

Electron 可使用 `desktopCapturer` 获取屏幕源，然后在渲染层做截图选区。

基本流程：

1. 主进程获取屏幕源。
2. 创建全屏透明截图 Overlay 窗口。
3. Overlay 窗口显示屏幕快照。
4. 用户拖拽选择区域。
5. Canvas 裁剪选区。
6. 生成图片 Blob / Buffer。
7. 根据用户动作复制、保存或创建贴图窗口。

---

## 12.3 贴图窗口实现思路

每个贴图对应一个独立 BrowserWindow。

窗口配置建议：

```ts
{
  frame: false,
  transparent: true,
  alwaysOnTop: true,
  resizable: true,
  skipTaskbar: true,
  hasShadow: true
}
```

贴图管理器负责：

1. 创建贴图窗口。
2. 管理窗口位置。
3. 管理置顶状态。
4. 管理透明度。
5. 管理关闭和销毁。
6. 管理多贴图列表。

## 12.4 图片存储

图片存储分两类：

### 临时图片

用于：

* 当前截图。
* 当前贴图。
* 未保存截图。

存储位置：

```text
appData/LiteLauncher/tmp/snap/
```

### 历史图片

用于截图历史。

存储位置：

```text
appData/LiteLauncher/screenshots/
```

SQLite 表设计：

```sql
CREATE TABLE screenshot_history (
  id TEXT PRIMARY KEY,
  file_path TEXT NOT NULL,
  width INTEGER NOT NULL,
  height INTEGER NOT NULL,
  source TEXT NOT NULL,
  created_at INTEGER NOT NULL,
  pinned INTEGER DEFAULT 0,
  deleted INTEGER DEFAULT 0
);
```

## 12.6 权限与安全

安全原则：

1. 截图、剪贴板、文件保存均在本地执行。
2. 不上传截图。
3. 不读取用户未授权目录。
4. 不把图片内容写入日志。
5. 云 OCR 默认关闭。
6. 插件不暴露完整 Node 能力给 renderer。
7. IPC 参数做校验。

隐私声明：

> LiteSnap 所有截图和贴图数据默认保存在本地，不会上传到任何服务器。

## 16. 风险与解决方案

### 16.1 多屏幕 DPI 问题

风险：

* Windows 多屏幕不同缩放比例时，截图区域可能偏移。

解决方案：

1. 优先测试 100%、125%、150% 缩放。
2. 截图坐标统一转换为 physical pixel。
3. Overlay 窗口按 display bounds 创建。
4. 每个 display 单独处理坐标。

---

### 16.2 Electron 截图性能问题

风险：

* 屏幕截图大图处理可能卡顿。

解决方案：

1. 尽量避免频繁全量重绘。
2. Canvas 操作只处理选区。
3. 大图保存放到主进程异步处理。
4. 历史缩略图单独生成。

---

### 16.3 贴图窗口过多

风险：

* 用户创建大量贴图后占用内存。

解决方案：

1. 限制默认最大贴图数量，例如 20 个。
2. 提供关闭所有贴图功能。
3. 贴图图片可压缩缓存。
4. 设置页允许用户调整最大贴图数量。

---

### 16.4 快捷键冲突

风险：

* 截图快捷键可能和其他软件冲突。

解决方案：

1. 首次启动检测快捷键注册是否成功。
2. 如果失败，提示用户修改。
3. 设置页允许自定义快捷键。

---

### 16.5 与 Snipaste 相似度过高

风险：

* 如果 UI、命名、交互完全照搬，会缺乏差异化。

解决方案：

1. 不使用 Snipaste 名称、图标、文案、UI 视觉。
2. 保留“截图贴图”这个通用体验，但做 LiteLauncher 自己的插件式体验。
3. 强调与启动器、剪贴板、开发者工具的联动。
4. 第一版功能轻量，不追求完全复制。

---

LiteSnap 不应该只是 Snipaste 的复制品，而应该有 LiteLauncher 特色。

3. 截图后生成 Issue 附件。
4. 截图后 OCR 错误信息。
5. 截图后快速打开图片压缩工具。
6. 截图后识别二维码。
7. 截图后取色并复制 HEX。

---

### 17.4 本地优先

默认所有能力本地运行，不上传截图，不依赖云服务。

这可以成为推广时的核心卖点。

## 21. 总结

LiteSnap 的核心价值不是“又一个截图工具”，而是补齐 LiteLauncher 的视觉效率能力。

LiteLauncher 当前已经有启动器、剪贴板、开发者工具和插件能力。如果再加入截图贴图能力，就可以从“工具启动器”升级为“本地效率工作台”。

第一版最重要的目标只有一个：

> 让用户可以快速截图、简单标注、复制或贴到屏幕上，并且体验足够顺滑。

只要这个闭环做好，LiteSnap 就能成为 LiteLauncher 推广时最容易被普通用户理解的亮点功能。
