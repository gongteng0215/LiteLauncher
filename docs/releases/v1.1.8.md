# LiteLauncher v1.1.8 Release Notes

Release date: 2026-08-05

## Highlights

Auto-update failures now leave a safe, actionable diagnostic trail in Settings, while Command Center settings refresh their visible content immediately after an update or log action.

### Improvements

- The main-process updater reports terminal check failures through the existing error log store, once per check cycle.
- Update log entries include the stage plus current and target version context; error details are truncated and redact common token, authorization, password, secret, and API-key values.
- The System & Updates card now includes **Copy update diagnostics**, with current version, target version, support state, latest stage, and diagnostic information.
- Refreshing, clearing, or checking diagnostics redraws the active Settings overlay in place, so the visible card and error-log output no longer lag behind the saved state.
- Electron coverage verifies failed update status, persisted error logging, settings refresh, complete diagnostic copying, and credential redaction.

### Release validation

- Ran the complete Electron smoke suite and produced a Windows x64 NSIS/ZIP package locally.
- macOS release assets continue to include updater metadata. When Apple signing credentials are unavailable, the release remains explicitly unsigned.

## Suggested checks

1. Open **Settings → System & Updates**, click **Check for updates**, and use **Copy update diagnostics** if feedback is needed.
2. If an update check fails, open **Settings → Error logs** and confirm the latest entry includes its stage and version context without credentials.
3. Use the v1.1.7 Windows NSIS installer in a disposable test environment, then run the v1.1.8 installer to confirm an in-place upgrade retains the expected application data.
