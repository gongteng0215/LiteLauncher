# Clipboard Workbench 插件 PRD / 设计稿

> 版本：V1.0  
> 日期：2026-05-15  
> 文档类型：LiteLauncher 插件产品需求文档 / 设计规格  
> 插件名称：Clipboard Workbench  
> 建议插件 ID：`clipboard-workbench`  
> 首期重点：独立于现有 `clip` 的图文文件剪贴板工作台，支持自动采集、手动收藏、分组归档、批量回贴与安全控制  
> 平台重点：Windows 11 优先；macOS 作为存储与浏览兼容目标，自动连续粘贴先不承诺同等能力

> 当前背景：LiteLauncher 已有 `clip` 入口，但当前仅支持文本剪贴板历史的采集、检索、复制、删除和清空。`Clipboard Workbench` 不替代、不修改、不复用现有 `clip` 的行为，而是作为一个新的独立插件，承接图文文件混合剪贴板、归档管理和批量回贴工作流。

---

## 1. 一句话定位

**Clipboard Workbench 是 LiteLauncher 内置的多格式剪贴板工作台插件，用于安全记录、整理、检索和回贴文本、图片、截图与文件路径内容，并提供批量连续粘贴与合并后一次性粘贴能力。**

它解决的问题不是“能不能记住剪贴板”，而是“当用户频繁处理多段文本、多张图、多组文件和反复粘贴流程时，如何在一个稳定、可管理、可回退、可保护隐私的面板里完成高频工作”。

---

## 2. 产品边界

### 2.1 明确边界

- 这是一个**新插件**，不是对现有 `clip` 的升级改造。
- 现有 `clip` 继续保留为轻量文本历史入口。
- `Clipboard Workbench` 负责重度场景：
  - 图文文件混合记录
  - 收藏与分组
  - 置顶与标签
  - 批量操作
  - 多条内容的粘贴工作流
  - 敏感场景保护

### 2.2 与现有 `clip` 的关系

| 能力 | 现有 `clip` | Clipboard Workbench |
|---|---|---|
| 文本自动采集 | 是 | 是 |
| 图片 / 截图采集 | 否 | 是 |
| 文件路径采集 | 否 | 是 |
| 手动保存当前剪贴板 | 否 | 是 |
| 收藏 / 分组 / 标签 / 置顶 | 否 | 是 |
| 批量操作 | 否 | 是 |
| 批量连续粘贴 | 否 | 是 |
| 合并后一次粘贴 | 否 | 是 |
| 敏感模式 / 排除规则 | 否 | 是 |

### 2.3 非目标

MVP 不做以下内容：

1. 不修改现有 `clip` 的数据库表、UI 或快捷命令。
2. 不做云同步。
3. 不做 OCR。
4. 不做图片编辑或标注。
5. 不做跨设备共享。
6. 不做复杂权限系统。
7. 不承诺所有平台都支持同等“自动连续粘贴”成功率。
8. 不做 Office / Photoshop / 微信等应用定制粘贴适配。
9. 不做内容版本历史。
10. 不做分享链接、网络上传或远端备份。

## 3. 目标用户与核心场景

### 3.1 目标用户

- 需要频繁复制多段文本、代码片段、SQL、命令行参数的开发者
- 需要来回粘贴素材图、截图、文件路径的办公和运营用户
- 需要把一组内容分门别类保存并反复回贴的高频效率用户
- 对隐私和敏感内容记录有明确控制诉求的用户

### 3.2 核心场景

#### 场景 A：多段文本回贴

用户复制了 6 段发布文案和 2 段 SQL，希望在一个面板里看到它们、选中其中 3 段并按顺序回贴到当前应用，而不是手动反复切窗口。

#### 场景 B：图片素材临时池

用户复制多张截图、海报图和设计参考图，希望它们被自动记录为缩略图，可收藏、分组、预览、导出和重新回贴。

#### 场景 C：文件路径组装

用户在资源目录中复制多个文件，希望把这些路径保存成一组，之后能一次性恢复为文件列表或合并成路径文本。

#### 场景 D：敏感会话保护

用户开始处理验证码、密码、隐私图片，希望临时开启敏感模式，自动监听停止入库，只允许手动收藏。

#### 场景 E：重复工作流

用户经常把“一组文本 + 一张图 + 一组文件路径”粘贴到不同业务系统，希望通过收藏、分组、置顶和批量动作建立稳定流程。

目录入口：

- 标题：`Clipboard Workbench`
- 副标题：`图文文件剪贴板工作台、收藏、分组与批量回贴`

### 5.3 是否默认可见

建议默认可见，理由：

1. 与现有 `clip` 能力形成明显分层，不是重复插件。
2. 高价值高频，适合作为默认效率工具曝光。
3. 有明确视觉面板和交互闭环，不是一次性实验插件。

如落地为默认可见，需同步：

1. `src/main/plugins/index.ts` 注册 `clipboard-workbench`
2. `DEFAULT_VISIBLE_PLUGIN_IDS` 包含 `clipboard-workbench`
3. `CURRENT_DEFAULT_VISIBLE_PLUGIN_IDS` 包含 `clipboard-workbench`
4. 老用户升级策略决定是否加入 `REQUIRED_VISIBLE_PLUGIN_IDS`
5. `test:plugins-visible` 覆盖入口搜索、命中和 Enter 打开

## 6. 信息架构与界面设计

### 6.1 总体结构

插件面板采用**顶部工具条 + 左栏分组 + 中栏列表 + 右栏详情**的三栏工作台结构。

```text
Clipboard Workbench
├── 顶部工具条
│   ├── 搜索框
│   ├── 监听状态开关
│   ├── 敏感模式开关
│   ├── 保存当前剪贴板
│   └── 批量动作入口
├── 左栏
│   ├── 全部
│   ├── 最近
│   ├── 收藏
│   ├── 置顶
│   ├── 文本
│   ├── 图片
│   ├── 文件
│   ├── 截图
│   └── 自定义分组
├── 中栏
│   ├── 条目列表
│   ├── 多选状态
│   ├── 批量操作条
│   └── 空状态 / 加载状态
└── 右栏
    ├── 预览
    ├── 详情元数据
    ├── 标签 / 备注 / 分组编辑
    └── 单条动作
```

### 6.2 左栏设计

左栏分为两段：

- 系统分类
- 自定义分组

系统分类固定存在：

- 全部
- 最近
- 收藏
- 置顶
- 文本
- 图片
- 文件
- 截图

### 6.3 中栏设计

列表项按类型展示不同摘要：

- 文本：
  - 第一行显示首行摘要
  - 第二行显示长度、标签、分组、时间
- 图片 / 截图：
  - 显示缩略图
  - 显示分辨率、大小、时间
- 文件路径：
  - 显示第一个文件名
  - 显示条目数、路径摘要、时间

中栏支持：

- 单选
- 多选
- Shift / Ctrl 风格连续和离散多选（按项目现有快捷交互习惯决定最终键位）
- 选中后显示批量操作条

### 6.4 右栏设计

右栏详情区按类型显示：

- 文本：全文预览
- 图片 / 截图：大图预览
- 文件路径：文件列表

下方统一展示：

- 标题
- 标签
- 分组
- 备注
- 来源
- 类型
- 大小
- 创建时间
- 最近回贴时间

动作按钮：

- 恢复到剪贴板
- 导出
- 收藏 / 取消收藏
- 置顶 / 取消置顶
- 删除

### 6.5 批量操作设计

多选后中栏底部展示批量操作条：

- 连续逐条粘贴
- 合并后一次粘贴
- 移动到分组
- 收藏 / 取消收藏
- 导出
- 删除

### 6.6 小屏与高 DPI

小屏下降级为：

- 顶部工具条
- 左栏折叠为下拉筛选
- 中栏与右栏改为上下布局

要求：

- 核心按钮不横向溢出
- 文本摘要不撑爆
- 图片缩略图不挤压成不可识别状态

建议仍使用现有 `settings` 表存放插件级 JSON：

`plugin.clipboard-workbench.settings`

建议结构：

```json
{
  "version": 1,
  "autoCollect": true,
  "sensitiveMode": false,
  "maxItems": 50,
  "maxBytes": 536870912,
  "ignoreShortCodes": true,
  "shortCodeLengthMax": 8,
  "ignoredAppHints": [],

```

### 7.4 资源目录

图片和截图不直接写入 SQLite，统一落盘到：

```text
<userData>/clipboard-workbench/assets/
```

原因：

- 避免大对象把 SQLite 膨胀得不可控
- 空间回收更直接
- 导出与预览更方便

## 8. 采集、去重与回贴流程

### 8.1 自动采集流程

```text
系统剪贴板变化
→ 判断当前是否暂停监听 / 敏感模式
→ 读取剪贴板内容
→ 类型识别
→ 排除规则检查
→ 生成标准化条目
→ 计算哈希
→ 去重或刷新时间
→ 存储条目
→ 触发容量回收
```

### 8.2 手动保存流程

```text
用户点击“保存当前剪贴板”
→ 主进程立即读取当前剪贴板
→ 类型识别
→ 存储为新条目或按哈希去重刷新
→ 返回成功反馈
```

### 8.3 去重策略

- 文本：按文本规范化内容哈希去重
- 图片：按二进制内容哈希去重
- 文件路径：按规范化路径数组哈希去重

若命中已有条目：

- 不重复插入新条目
- 更新时间戳
- 如来源更完整，可补齐摘要字段

### 8.4 单条回贴

#### 文本

- 写回系统剪贴板文本

#### 图片 / 截图

- 从缓存文件重建图片对象
- 写回系统剪贴板图片

#### 文件路径

- 以系统允许的路径列表或文本形式写回
- MVP 以“路径文本列表”作为保底模式

### 8.5 批量连续逐条粘贴

流程：

```text
用户多选条目
→ 点击“连续逐条粘贴”
→ 校验类型是否可参与批量
→ 按选中顺序逐条恢复系统剪贴板
→ 尝试向当前活动应用发送粘贴动作
→ 记录成功 / 失败统计
```

策略：

- Windows 11 优先实现
- 先做“最佳努力”
- 如果系统级自动粘贴失败：
  - 立即停止后续自动发送
  - 给出状态提示
  - 当前条目仍已恢复到系统剪贴板，可手动粘贴

### 8.6 合并后一次性粘贴

#### 文本多选

支持：

- 直接拼接
- 换行拼接
- 空行拼接
- 自定义分隔符

#### 文件路径多选

支持：

- 一行一个路径
- 用分隔符拼接成单文本

#### 图片多选

MVP 不做“多图合成一张图”，多图多选默认提示使用“连续逐条粘贴”。

## 9. 安全与隐私设计

### 9.1 基础安全能力

- 暂停监听
- 一键清空全部历史
- 单条删除
- 批量删除

### 9.2 敏感会话模式

开启后：

- 自动监听不再新增条目
- 用户仍可手动保存当前内容
- 顶部显著提示当前处于敏感模式

### 9.3 简单排除规则

MVP 建议支持：

- 忽略过短纯数字验证码
- 忽略典型一次性验证码文本
- 为后续应用来源排除预留字段

### 9.4 日志与错误处理

要求：

- 不把真实正文、图片内容、完整路径写入错误日志
- 日志只记录类型、大小、动作阶段和错误摘要
- 敏感条目删除后要同步删除资源文件

## 10. 容量与清理策略

### 10.1 默认策略

- 默认最大条目数：`50`
- 默认总空间上限：建议 `512 MB`

用户可修改：

- 最大条目数
- 总空间上限

### 10.2 淘汰策略

触发清理时：

1. 优先删除最旧的、非置顶、非收藏条目
2. 再删除最旧的收藏条目
3. 置顶条目最后才参与清理

如所有条目都被置顶且超过上限：

- 返回明确提示
- 不 silent fail

### 10.3 资源清理

- 删除条目时删除对应资源文件
- 清空全部时清空资源目录中的受管文件
- 启动时做一次孤儿资源巡检

## 11. 技术架构设计

### 11.1 分层

```text
src/main/plugins/clipboard-workbench/
├── index.ts        # 插件入口、命令分发、openPanel
├── service.ts      # 编排层：读写、搜索、批量操作、容量回收
├── collector.ts    # 系统剪贴板监听与类型识别
├── store.ts        # SQLite 与资源文件读写
├── paste.ts        # 单条回贴、批量粘贴执行
└── types.ts        # 主进程内部类型

src/shared/clipboard-workbench.ts
└── 共享类型、枚举与纯函数 helper

src/renderer/plugin-panel-impls.ts
└── renderClipboardWorkbenchPanel / applyClipboardWorkbenchPanelPayload
```

### 11.2 关键原则

- 采集逻辑不写进 `renderer.ts`
- 资源文件路径只由主进程管理
- UI 只消费标准化条目结构
- 粘贴执行层和存储层解耦
- 排除规则和合并策略尽量做成纯函数，便于测试

- 敏感模式下自动监听不入库

### 13.2 UI 验收

- 敏感模式有效
- 删除条目后资源文件同步删除

## 15. 风险与应对

### 风险 1：自动连续粘贴在不同应用表现不一致

应对：

- MVP 写成“Windows 优先、最佳努力”
- 失败时降级到“恢复到系统剪贴板”
- 明确用户提示，不承诺 100% 自动成功

### 风险 2：图片资源导致空间膨胀

应对：

- 双限制
- 资源文件独立落盘
- 启动时巡检孤儿文件

### 风险 3：误记录敏感内容

应对：

- 敏感模式
- 短验证码排除
- 一键暂停监听

### 风险 4：与现有 `clip` 概念混淆

应对：

- 不抢占 `clip`
- 搜索关键词使用 `clipx` / `clipboard`
- README 与文档中明确区分两者定位

## 16. README 文案建议

```md
### Clipboard Workbench

LiteLauncher 内置的多格式剪贴板工作台插件。

它独立于现有 `clip`，支持记录文本、图片、截图和文件路径，提供收藏、分组、置顶、批量回贴、合并粘贴和敏感模式等能力，适合重度剪贴板工作流。

默认支持自动监听和手动保存当前剪贴板；自动连续粘贴在 Windows 上按最佳努力方式实现，失败时会降级为恢复到系统剪贴板。
```

## 17. 结论

`Clipboard Workbench` 最合适的落地方式不是去改造现有 `clip`，而是作为一个新的独立工作台插件存在：

1. 保持现有轻量能力稳定。
2. 让重度工作流拥有明确的独立边界。
3. 在主进程中安全管理多格式采集、资源文件与回贴动作。
4. 在渲染层提供一致的三栏管理工作台。
5. 以 Windows 优先和最佳努力策略，先把批量粘贴工作流真正落地。
